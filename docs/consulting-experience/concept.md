# 制作方針・全体構成

## 1. 結論

- 60分の体験は、**導入動画（既存・約4分30秒）＋ 5フェーズ・7つの問い（21分岐）＋ 実機デモの実測記録 ＋ 振り返り**で構成する。
- 映像は、**選んだ選択肢ごとに専用のクリップ（39本）**を Remotion で作る。体験アプリ（React）がそれを分岐再生する。
- 45分すべてを動画にはしない。体験中に流す映像は1回の進行で**約5分**。残りは考える・選ぶ・話し合う・実機で確かめる時間に使う。
- 実写・公式製品画像・実機映像は、まだ1点も手元にない。現状は**線画CGと仮素材**で動く。届いた素材は、所定の場所に置くだけで差し替わる設計にした。

## 2. 制作の優先順位（マスタープロンプトどおり）

1. 学生が主体的に質問・判断・提案できる → 選択肢を出す前に「考える時間（30〜60秒）」を挟む。推奨の選択肢は、進行役が「解説を表示」するまで出さない。
2. 選んだ選択肢と映像が一致する → 21分岐すべてに別々の映像を割り当てた。`npm run experience:validate` で、同じ映像の使い回しを機械的に検出する。
3. センシング技術の価値が伝わる → Phase2 は光の原理のCG、Phase4 は製品紹介、Phase5 は実機検証。
4〜6. 映像のリアルさ・飽きさせない・応募意欲 → 30〜60秒ごとに、考える・選ぶ・観察する場面を入れる。最大の山場は実機デモ。

## 3. 全体構成

| 区分 | 時間 | 中身 | 映像（1回の進行で流す分） |
|---|---|---|---|
| 01 導入・MISSION理解 | 5分 | 既存の導入動画 → MISSION の板書 | 約4分30秒 |
| Phase1 現状確認 | 7分 | お客様の相談 → 問い1（A/B/C） | 約30秒 |
| Phase2 原因の深掘り | 9分 | 問い2 → 解説「透明なボトルと光」→「どこで数が増えている？」 | 約1分20秒 |
| Phase3 真因・顧客課題 | 9分 | 問い3 → 解説「本当の課題」 | 約40秒 |
| Phase4 解決提案 | 8分 | お客様の要望 → 問い4 → 製品紹介 → 30秒の提案トーク | 約1分10秒 |
| Phase5 実機デモ・検証 | 12分 | STEP1 問い5 → 検証項目と合格基準 → STEP2 実機 → STEP3 問い6・悪条件3つ → STEP4 問い7 | 約1分30秒＋実機 |
| 03 振り返り | 10分 | Q1〜Q4 → 現場のモンタージュ → エンディング | 約35秒 |

詳細な時間割は [schedule.md](schedule.md)、全セリフは [script.md](script.md)、映像設計は [storyboard.md](storyboard.md)。

## 4. 既存台本（導入動画 9シーン）との差分

**方針**：既存の導入動画は変更していない。内容を消したり上書きしたりもしていない。気になる点は「改訂案」として下に挙げ、承認があれば反映する。

### 継承したもの

| 既存シーン | 体験への引き継ぎ |
|---|---|
| 03 MISSION（飲料工場・誤カウント） | 同じ「LINE 03」、同じカウント表示（実際の本数／センサのカウント）で Phase1 につなぐ |
| 04 何を確認する？ | 導入では問いかけだけ。答えは Phase1 で学生自身が選ぶ |
| 05 お客様が実現したいこと | Phase3 の「本当の課題」、Phase4 の「交換ではなく一緒に確かめる」へ |
| 06 放っておくと何が起きる？ | Phase3 の連鎖図（誤カウント → 数量不一致 → 確認作業 → 作業負担 → 生産効率） |
| 07 光電センサの基本 | Phase2（透明体と光）と Phase4（透明体検出センサ）で、課題と結びつけて掘り下げる |
| 08 YOUR MISSION「まずはお客様に現状を確認します」 | Phase1 の最初の問いへ直結 |

### 改訂案（未反映。判断をお願いしたい点）

| # | 対象 | 問題 | 改訂案 |
|---|---|---|---|
| 1 | 導入 Scene03 のセンサ配置 | 導入ではセンサが**真上から下向き**に光を出している。この配置は拡散反射型に見える。体験の Phase2 では、お客様が「センサは片側、反対側に反射板」（回帰反射型）と答えるため、設備の位置関係が食い違う | Scene03 の絵を、体験と同じ LINE 03 の配置（手前にセンサ、奥に反射板）に描き直す |
| 2 | 導入 Scene07（約2分15秒） | 全体の約半分を占める。体験の Phase2・Phase4 でも透明体の検出を扱うので重複する | 導入では「方式によって得意・不得意がある」まで（60〜70秒）に絞る。細部は体験で課題と結びつけて扱う |
| 3 | 導入 Scene02・08 の4ステップ | 新しいコンセプトは「聞く。考える。提案する。**そして、確かめる。**」。導入の4ステップに「確かめる」がない | 4ステップの最後に「確かめる」を加え、5ステップにする |

## 5. マスタープロンプトに対する指摘（目的とのズレ・リスク）

| # | どこが問題か | なぜ問題か | どう直すか |
|---|---|---|---|
| 1 | 実写70%の想定 | 実写の素材が現時点で0本。撮影しなければ「企業紹介動画の品質」にはならない | [asset-license-check.md](asset-license-check.md) の撮影リストで、人物・工場・実機を一度にまとめて撮る。届くまでは線画CGで運用する |
| 2 | 主役製品 KR-Q | 一覧ページに「生産終了機種」との表記があるという検索結果がある（公式ページは未確認）。終了品なら Phase4・5 の前提が崩れる | 制作前に、現行の透明体検出センサの型式を社内で確定する。画面の型式は「確認中」と表示している |
| 3 | 選択肢 C（交換・予算・価格） | 明らかに外れと分かるため、学生が「正解当て」をしやすい | 本番前に、もっともらしい別の選択肢へ差し替えを検討する。例：P3-C「ずれは何本くらいですか？」。データを直すだけで差し替わる |
| 4 | 推奨以外を選んだ班 | Phase2 はお客様の「流れが乱れたとき」という発言（P1-B の情報）から始まる | 比較画面で全員がBの情報を確認してから進む（進行役メモに明記） |
| 5 | 実機デモの合否 | 結果を事前に約束できない | 実測を記録し、基準を満たさない場合は「追加調査」へ分岐するようにした（成功を作らない） |
| 6 | 60分の密度 | 問い7つ ×（考える＋話し合い＋比較）と、提案トークの発表で余裕が少ない | 予備の時間は各フェーズ1分程度。押したときは、Phase3 の討議と振り返り Q3 を短くする |
| 7 | Remotion の利用条件 | Remotion は、一定規模以上の企業での利用に有償の会社ライセンスが必要（公式サイトの条件を要確認） | 社内で購入の要否を確認する（[asset-license-check.md](asset-license-check.md) に記載） |
| 8 | ナレーション・お客様の声 | 音声合成（ElevenLabs）は利用できない状態。今は字幕のみ | 音読さん用のセリフを `out/experience/ondoku/` に書き出した。お客様役は実写撮影のときに同時録音するのが最善 |

## 6. 事実・仮説・演出・検証結果の区別

| 区分 | 扱い |
|---|---|
| 事実 | メーカー公式情報で確認できたことだけを書く（[technical-review.md](technical-review.md)）。型式・仕様値は、確認できるまで出さない |
| 仮説 | 「透明体は条件によって受光量の変化が小さく、出力が複数回切り替わる可能性がある」。画面には「可能性」「条件しだい」と明記する |
| 演出 | 工場・お客様・記録データは教育用の架空設定。記録の画面に「教育用の架空データ」と表示する |
| 検証結果 | 実機の実測値だけ。シミュレーション映像には常に「シミュレーション　実測結果ではありません」と表示する |
