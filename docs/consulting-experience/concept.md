# 制作方針・全体構成

## 1. 結論

- タイトルは **「YOUR MISSION ペットボトルの誤カウントを解決せよ！」**（OPTEX-FA CONSULTING SALES EXPERIENCE）。
- 60分は **導入5分 → 聞く10分 → 考える10分 → 課題を見つける10分 → 提案する・実機デモ15分 → 振り返り10分**。
- 導入は既存の導入動画（約4分30秒）をそのまま使う。新しい導入動画は作らない。導入動画の最後に出てくる4つのステップ（聞く・考える・課題を見つける・提案する）が、そのまま体験の4フェーズになる。
- 学生は **10の問い（30の選択肢）** に答える。選んだ選択肢ごとに、専用の映像・お客様の回答・分かったこと・まだ分からないことが出る。
- 推奨の選択肢は**回答後に理由とともに**示す。推奨以外を選んでも先へ進める（違いを比べることが学びになる）。
- 最大の山場は実機デモ。映像はシミュレーション（見方の説明）までにとどめ、結果は実機で確かめる。

## 2. 体験の設計思想

| 狙い | 仕掛け | なぜそうするか |
|---|---|---|
| 主体的に考える | 選択肢を出す前に「考える時間（30〜45秒）」 | 選択肢を見てから考えると、消去法になる |
| 選択と結果が一致する | 30の選択肢すべてに別々の映像 | 同じ映像の使い回しは、選択の意味を薄める。`npm run experience:validate` で機械的に検出 |
| 正解探しにしない | 推奨は回答後に表示。推奨なしの問い（P2-Q1）もある | 現場の営業は「どれも大事」から優先順位を決める |
| 足りない情報に気づく | 回答後に「分かったこと」と「まだ分からないこと」を並べる | 次の質問を考える材料になる |
| 一人で詰まらない | 先輩社員（森さん・中田さん）のヒントを必要なときだけ表示 | 答えは言わず、考え方の手がかりだけ渡す |
| 確かめる文化を伝える | 実機デモ前に予想 → 実機で結果を記録 → 基準未達なら追加調査へ | 「売るだけでは終わらない」を体験で理解する |

## 3. 4フェーズの構成

| フェーズ | 目的 | 問い | 学生が得るもの |
|---|---|---|---|
| 導入（5分） | 営業の役割と今回のミッションを理解 | 導入動画の3か所で一時停止 | 「聞く・考える・課題を見つける・提案する」の全体像 |
| PHASE 1 聞く（10分） | お客様の相談を具体的に理解 | P1-Q1・P1-Q2 | 問題の大きさ（通常+0.5〜0.8%、最大+3.0%）と起きる条件 |
| PHASE 2 考える（10分） | 原因の候補を整理 | P2-Q1・P2-Q2 | 透明体と光の関係、センサ出力とPLCカウントの切り分け |
| PHASE 3 課題を見つける（10分） | 誤カウントの先の顧客課題を理解 | P3-Q1・P3-Q2 | 本当の課題＝正確な数量管理と確認作業の負担 |
| PHASE 4 提案する（15分） | 解決仮説を提示し、実機で検証 | P4-Q1〜P4-Q4 | 実機で、悪条件も含めて一緒に確かめる提案 |
| 振り返り（10分） | 体験を自分の言葉にする | Q1〜Q4 | 営業の仕事とOPTEX-FAの技術の理解 |

場面ごとの流れは [complete-story.md](complete-story.md)、全セリフは [dialogue-script.md](dialogue-script.md)、問いと選択肢は [question-list.md](question-list.md)。

## 4. 1つの問いの流れ

```
短い導入映像 → お客様のセリフ → 問い → 考える時間 → A/B/C → 選ぶ
→ 専用映像（営業のセリフ → お客様の回答） → 分かったこと／まだ分からないこと
→ 推奨と理由・短い解説 → 次へ
```

進行役は「ほかの選択肢の結果を表示」で、選ばなかった選択肢の回答も見せられる。

## 5. 技術表現のルール（要約）

詳細は [technical-rules.md](technical-rules.md)。

- センサは**透明体検出用の回帰反射型**（投光・受光一体）。センサを片側に横向き、反射板を反対側に同じ高さで正対させる。検出位置は**ボトルの下部**（側面から）。
- 光は「センサ → ボトルの下部 → 反射板 → 同じセンサ」と往復する。反射板は光を出さず、受けもしない。映像では行きと戻りを分けて描く。赤い光の線は**説明用の表現**。
- 誤カウントは**常に実際より多い**（過剰カウント）。通常+0.5〜0.8%、最大+3.0%（毎週3%ではない）。数値は**研修用の架空データ**。
- 調査では、センサの出力とPLCのカウントを分けて確認する。
- 実測値・成功結果を作らない。シミュレーションには「シミュレーション」と明記する。

## 6. 現状の制作状態

- 映像は Remotion の線画CG（仮素材）で全48本を制作済み。実写・実機映像・公式製品画像・音声は、届いたら所定の場所に置くだけで差し替わる（[recording-guide.md](recording-guide.md)）。
- 実写風の動画は生成していない（生成できる契約がないため）。生成用のプロンプトは [generation-prompts.md](generation-prompts.md) に用意した。
- 外部サービスの利用・費用・メーカー画像の使用許諾は、ご判断待ち（[README.md](README.md) の「ご判断が必要な事項」）。
