# 技術表現のルール（v3）

映像・セリフ・資料・画像生成のすべてに適用する。`npm run experience:validate` が一部を機械的に検査する（最後の表）。表現ごとの確認状況は [technical-review.md](technical-review.md)。

## 1. センサ配置のマスター（全シーン共通）

基準図は `src/experience/remotion/v4/Layout.tsx`（上から見た図・搬送方向から見た図）と、導入動画のライン（`src/consulting/components/Conveyor.tsx`：センサは手前、反射板は奥、ボトル下部の高さ）。

| 項目 | 固定する内容 |
|---|---|
| 搬送方向 | 左 → 右 |
| センサ | **投光・受光一体**の回帰反射型。コンベアの**片側**に**横向き**。レンズは反射板を向く |
| 反射板（リフレクタ） | **反対側**に、センサと**同じ高さ**で**正対**。光を戻すだけ（光を出さない・受けない） |
| 検出位置 | ボトルの**下部**（底から約20%）を**側面から** |
| 光の経路 | センサ → ボトル下部 → 反射板 → **同じセンサ**。行きと戻りを分けて描く。赤い線は**説明用の表現** |
| やってはいけない | 反射板から光を出す／反射板を受光器として描く／キャップ・肩・上部を検出する／反射板をセンサと同じ側に置く／画像ごとに向きを反転させる／透過型（投光器・受光器が別体）と混同する |

## 2. 既設センサと提案センサ

| | 既設センサ | 提案センサ |
|---|---|---|
| 表現 | 「既設の**他社製**回帰反射型光電センサ」 | 「OPTEX-FA **KR-Qシリーズ**（透明体検出タイプ・回帰反射型）」 |
| メーカー・型式 | OMRON または KEYENCE の実製品を候補にするが、型式と用途が確認できるまで**表示しない** | 型式（例：KR-Q50N・KR-Q150NW・KR-Q300NW）・仕様は**公式資料で確認してから**表示 |
| 画像 | 公式画像（許諾済み）か、ロゴのない汎用の表現 | **公式画像のみ**。AIで外観を作らない |
| 言い方 | 透明体専用とは限らない。**欠陥品と言わない・描かない**。メーカーを原因と決めつけない | 機能の違いは**公式資料に基づいて**説明。「他社製品より必ず優れている」とは言わない |

## 3. 誤カウントのデータ

| 項目 | ルール |
|---|---|
| 性質 | 常に**実際より多い**（過剰カウント）。検出漏れ・少なく数える話にすり替えない |
| 数値 | 実際10,000本に対し 10,060（+0.6%）／10,300（+3.0%）／10,050（+0.5%）／10,080（+0.8%） |
| 言い方 | 通常 +0.5〜0.8%、多い週だけ最大 +3.0%。**毎週3%とは言わない** |
| 表示 | 数値の出る画面には「研修用の架空データ」と表示 |

## 4. 原因の扱い

- 候補：ボトルの揺れ／ボトル下部の凹凸／透明体の屈折・反射による受光量の変化／光軸・感度の設定／反射板の状態／PLC側の計数処理／電気ノイズ。最初から確定しない。
- 研修内では、調査と**仮想検証（研修用シミュレーション）**で「受光量の不安定さ」と「1本の通過中の複数信号」を主な仮説として絞り込む。仮想検証は実測ではないと必ず表示する。
- 調査では、**センサの出力**と**PLCのカウント**を分けて記録する。

## 5. 比較デモと結果

| 項目 | ルール |
|---|---|
| 同じにする | ボトル・搬送速度・設置の高さ（ボトル下部）・設置環境・再現する悪条件 |
| 各センサに合わせる | 反射板・設定（各メーカーの使用条件を満たす） |
| 記録する | センサごとに：通過本数・センサの出力回数・PLCのカウント値・1本の通過中の出力の切り替わり → 判定と過剰率 |
| 結果の区分 | **1. 実測データ**（記録した値）／**2. 研修用シミュレーション**（見方の説明）／**3. 期待する改善効果**（見込み。数値は出さない） |
| 改善後の数値 | **実測値が得られるまで未確定**。+0.1〜0.3% などを実績として出さない |
| 成功のセリフ | 「この条件では正しく数えられましたね」は、KR-Qシリーズの実測が基準を満たしたときだけの想定シナリオ（P4-Q3 はその条件でだけ出る） |

- お客様：佐藤さん（設備課）・高橋さん（品質管理課）＝白い衛生作業服と白い衛生帽。OPTEX-FA：森さん（営業）・中田さん（アプリケーションエンジニア）＝淡いブルーグレーの作業ジャンパーと白い衛生帽。スーツで製造ラインに入らない。装飾品なし。
- 映像に人物の写真・イラストは出さない（導入動画と同じ）。話者はラベル（お客様／OPTEX-FA）・部署・名前で示す。
- 画像の中に**文字・ロゴ・名札を入れない**。字幕・説明・グラフは動画側で重ねる。生成AIの誤字を使わない。
- 同じ画像の使い回しは、カメラの寄り・引きと重ねる情報を変えて最小限にする。

## 7. 自動検査（`npm run experience:validate`）

| 検査 | 内容 |
|---|---|
| 過剰カウント | 「少なくカウント」「検出漏れが原因」などの言い回しがないか |
| 反射板 | 「反射板が光を出す／受ける」などの言い回しがないか |
| 数値 | 「0.5〜0.8%」と「3%」が台本にあるか。「改善後 +0.1〜0.3%」のような実測前の数値がないか |
| 分岐 | 選択肢ごとに別の映像か、背景映像と重複しないか、行き止まりがないか |
| 映像 | 場面（overlay）が描けるか、切り替え位置が範囲内か |
| 画像 | 生成済みの画像ファイルがあるか、プロンプトに「文字なし」があるか、未生成・要確認の画像の一覧 |
| 時間 | フェーズの合計が60分か |
