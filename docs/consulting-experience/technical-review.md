# 技術表現の確認結果

`src/experience/data/phases.json`（ナレーション・セリフ・ヒント・learningPoint・technicalInsight）と用語集 `glossary.json` で使っている技術的な表現を、1つずつ確認した結果です。

**確認の方法**：メーカー公式サイトは、この制作環境から直接開けなかった（プロキシで遮断）。公式ドメインに限った検索結果の抜粋で照合した。詳細は [research/product-facts.md](research/product-facts.md)。
**残っている作業**：「公式資料での確認待ち」の項目は、社内の技術担当が公式資料と照合してから本番に使う。

状態の区分

- **一般的な原理として妥当**：特定製品に依存しない光電センサ・計数の基本。言い切り方も確認済み
- **公式資料での確認待ち**：製品名・仕様・現行品かどうかに関わる。直接照合が必要
- **演出・説明用**：研修のための表現・架空データ。画面上で明示している
- **使っていない**：根拠が弱いため、画面・セリフに出していない

## 実機デモでの数値の扱い

- アプリに入力した実測値だけを「結果」とする。シミュレーションの数値は結果として扱わない。
- 判定の基準：**通過させた本数＝カウント値**、かつ**1本の通過中に出力が何度も切り替わらない**。3項目のどれかが空欄なら判定しない。
- 通常条件が基準を満たさない・未記録なら P4-Q3 を、悪条件までのどれかが満たさない・未記録なら P4-Q4 を出さない。代わりに `p4-followup`（結果が基準に届かなかったとき）へ進む。
