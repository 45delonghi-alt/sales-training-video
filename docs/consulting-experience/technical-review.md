# 技術表現の確認結果

`src/experience/data/phases.json`（v3：ナレーション・セリフ・ヒント・learningPoint・technicalInsight・facilitatorNote）と用語集 `glossary.json` で使っている技術的な表現を、1つずつ確認した結果です。

**確認の方法**：メーカー公式サイトは、この制作環境から直接開けなかった（プロキシで遮断）。公式ドメインに限った検索結果の抜粋で照合した。詳細は [research/product-facts.md](research/product-facts.md)。
**残っている作業**：「公式資料での確認待ち」の項目は、社内の技術担当が公式資料と照合してから本番に使う。

状態の区分

- **一般的な原理として妥当**：特定製品に依存しない光電センサ・計数の基本。言い切り方も確認済み
- **公式資料での確認待ち**：製品名・仕様・現行品かどうかに関わる。直接照合が必要
- **演出・説明用**：研修のための表現・架空データ。画面上で明示している
- **使っていない**：根拠が弱いため、画面・セリフに出していない

## 比較デモでの数値の扱い

- アプリに入力した実測値だけを「結果」とする。シミュレーション・仮想検証の数値は結果として扱わない。
- 記録するのは、条件ごと・センサごと（既設センサ／KR-Qシリーズ）に：通過させた本数、センサの出力回数、PLCのカウント値、1本の通過中に出力が何度も切り替わったか（あり／なし）。あわせて過剰率を表示する。
- 判定の基準：**通過本数＝出力回数＝カウント値**、かつ**切り替わりなし**。4項目のどれかが空欄なら判定しない。
- P4-Q3 の表示は **KR-Qシリーズの記録だけ**で判定する。既設センサの記録は比較のために表示し、判定には使わない。
- 結果は「1. 実測データ　2. 研修用シミュレーション　3. 期待する改善効果」に分けて示す。実測していない改善後の数値は出さない。
