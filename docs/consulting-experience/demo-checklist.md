# 実機デモ　準備チェックリスト

PHASE 4 の実機デモ（5条件）を、安全に・正直に行うための準備リストです。
デモの目的は「うまくいく場面を見せること」ではなく、**お客様と一緒に、本当に数えられるかを確かめること**です。

| sceneId | 条件 | 確認すること |
|---|---|---|
| `p4-demo-normal` | 通常条件（一定の間隔・位置で流す） | 1本につき信号が1回だけか／実際の本数・センサの出力回数・カウント値が一致するか |
| `p4-demo-wobble` | 悪条件① ボトルの揺れ | 揺れても1本につき信号1回か／カウントが増えるタイミングがボトルの通過と合っているか |
| `p4-demo-offset` | 悪条件② 位置ずれ（センサ側・反射板側にずれる） | 位置がずれても1本につき信号1回か／カウント値が実際の本数と一致するか |
| `p4-demo-gap` | 悪条件③ 間隔の変化（ボトルどうしが詰まる） | 詰まったボトルを1本ずつ区別できるか／カウント値が実際の本数と一致するか |
| `p4-demo-shape` | 悪条件④ ボトル形状の違い（くびれ・凹凸・容量） | 形が違っても1本につき信号1回か／カウント値が実際の本数と一致するか |

## 1. 設置のルール（必ず守る）

- [ ] センサは **透明体検出用の回帰反射型センサ（投光・受光一体）** を使う
- [ ] センサを**コンベアの片側に横向き**で取り付けた
- [ ] **反射板を反対側に、センサと同じ高さで正対**させた
- [ ] 検出位置は **ボトルの下部（側面から）** にした。キャップや上部を検出位置にしていない
- [ ] 光の経路を説明できる：**センサ → ボトル下部 → 反射板 → 同じセンサへ戻る**
- [ ] 説明で「反射板が光を出す」「反射板が光を受ける」と言わない（反射板は光を戻すだけ。光を出して受けるのはセンサ本体）
- [ ] **透過型（投光器と受光器が別体）と混同しない**。反対側にあるのは受光器ではなく反射板

- [ ] 使用するセンサの**シリーズ・型式を確定**し、現行品であることを公式資料で確認した（型式：＿＿＿＿＿＿＿＿）
  - 候補の KR-Q シリーズは、現行品かどうか・正確な仕様が**未確認**（[research/product-facts.md](research/product-facts.md)）
- [ ] 取扱説明書で、検出距離・設置条件・反射板の種類を確認した

- [ ] 悪条件の範囲を決めた（**実際のラインで起こりうる範囲に限る**）
  - 揺れ：＿＿＿＿＿＿＿＿（揺らし方・大きさ）
  - 位置ずれ：センサ側・反射板側に ＿＿ mm まで
  - 間隔：最小 ＿＿ mm（接触させるか：する・しない）
  - 形状：使うボトル ＿＿ 種類（くびれ・凹凸・容量）

## 3. 用意するもの

- [ ] 実機：センサ本体・反射板・取付金具・ケーブル・電源
- [ ] ボトル：実物に近い透明PETボトル（中身入り・ラベル付き）＿＿本、形状違い ＿＿種類
- [ ] 検証台：小型コンベア、または手送り治具（ボトルを手で流すガイド）
- [ ] 計数：PLC またはカウンタ（センサ出力を数えるもの）
- [ ] センサ出力の確認手段：センサの表示灯が見える位置、またはロガー・オシロ等（＿＿＿＿＿＿）
- [ ] 記録用カメラ（表示灯とカウント値が同じ画面に入る位置）／書画カメラ（投影用）
- [ ] 予備：センサ・反射板・ケーブル・ボトル・電源タップ
- [ ] 清掃用品（レンズ・反射板の汚れは誤検出の原因）

## 4. 当日（開始30分前）

### 安全

- [ ] コンベアの可動部・挟まれ箇所にカバーがある。非常停止の位置を確認した
- [ ] 学生が立つ位置を決め、可動部に手が届かないようにした
- [ ] ケーブルを床で固定し、つまずかないようにした
- [ ] 電源・配線を確認した。ノイズ源（モーター・インバータ）から配線を離した
- [ ] 光源の注意事項（レーザ品の場合はクラス表示）を取扱説明書で確認した

### 準備

- [ ] 「1. 設置のルール」をもう一度確認した（片側・横向き／反射板は同じ高さで正対／検出はボトル下部）
- [ ] 光軸を調整し、レンズと反射板を清掃した
- [ ] 表示灯が学生から見える向きになっている（または書画カメラで投影）
- [ ] PLC／カウンタを接続し、0 にリセットした
- [ ] アプリの実機デモ画面で「実機（ライブ）」または「実機の動画」に切り替え、「実測を記録」の入力欄が使えることを確認した
- [ ] 記録用カメラの録画を開始した

## 5. 合格基準（アプリの判定と同じ）

各条件で、次の **すべて** を満たしたときだけ「合格」とする。

1. **通過させた本数 ＝ センサの出力回数**（表示灯・出力の記録で数える）
2. **通過させた本数 ＝ カウント値（PLC）**
3. **1本の通過中に、出力が何度も切り替わらなかった（切り替わり：なし）**

- センサの出力回数と PLC のカウント値を分けて記録することで、数が増えた場所（センサ側か PLC 側か）を切り分けられる。
- 4項目（通過本数・出力回数・カウント値・切り替わりの有無）のどれかが空欄なら、アプリは判定しない（成功扱いにならない）。
- 通常条件が不合格・未記録なら P4-Q3 は出ず、悪条件までのどれかが不合格・未記録なら P4-Q4 は出ず、「結果が基準に届かなかったとき（追加調査）」に進む。

## 6. デモ中

- [ ] 学生に予想を書いてもらった（ワークシートの「予想」欄）
- [ ] 本数を数える担当（学生1名）を決めた

- [ ] シミュレーション映像の数値を、結果として扱っていない
