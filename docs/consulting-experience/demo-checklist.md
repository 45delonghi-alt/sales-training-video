# 比較デモ　準備チェックリスト

PHASE 4 の比較デモ（4条件 × センサ2つ）を、安全に・公平に・正直に行うための準備リストです。
デモの目的は「KR-Qシリーズが勝つ場面を見せること」ではなく、**お客様と一緒に、同じ条件で本当に数えられるかを確かめること**です。

比べるセンサ

| 区分 | センサ | 扱い |
|---|---|---|
| 既設センサ | お客様が今使っている**他社製の回帰反射型光電センサ**（透明体専用かどうかは未確認） | メーカー名・機種名を画面や説明で出さない。原因と決めつけない。「不良」「欠陥」と言わない |
| 提案するセンサ | **OPTEX-FA KR-Qシリーズ**（透明体検出タイプ・回帰反射型） | 仕様は公式資料で確認した範囲だけを話す。「他社より必ず優れている」と言わない |

| sceneId | 条件 | 確認すること |
|---|---|---|
| `p4-demo-normal` | 通常搬送（一定の間隔・位置・速度で流す） | 1本につき出力が1回だけか／通過本数・出力回数・PLCのカウント値が一致するか |
| `p4-demo-wobble` | ボトルの揺れ（実際のラインで起こりうる範囲） | 揺れても1本につき出力1回か／カウント値が通過本数と一致するか |
| `p4-demo-gap` | 間隔の変化（ボトルどうしが詰まる） | 詰まったボトルを1本ずつ区別して出力が出るか／カウント値が通過本数と一致するか |
| `p4-demo-height` | 検出高さの比較（ボトル下部の基準位置と、その上下） | 高さで出力の安定性が変わるか／基準位置でカウント値が通過本数と一致するか |

---

## 1. 設置のルール（2つのセンサ共通・必ず守る）

- [ ] 搬送方向は**左 → 右**
- [ ] センサ（**投光・受光一体**）を**コンベアの手前側に横向き**で取り付けた
- [ ] **反射板を奥側に、センサと同じ高さで正対**させた
- [ ] 検出位置は **ボトルの下部（底から約20%）**。キャップや肩を検出位置にしていない
- [ ] 光の経路を説明できる：**センサ → ボトル下部 → 反射板 → 同じセンサへ戻る**
- [ ] 「反射板が光を出す」「反射板が光を受ける」と言わない（反射板は光を戻すだけ）
- [ ] **透過型（投光器と受光器が別体）と混同しない**。奥にあるのは受光器ではなく反射板
- [ ] 赤い光の線は説明用の表現であることを伝える（実際の光の色・見え方は機種による）

## 2. 同じ条件で比べるためのルール

- [ ] **同じボトル**（同じ容量・形状・ラベル・中身）を使う
- [ ] **同じ搬送速度**（コンベアの設定値：＿＿＿＿）
- [ ] **同じ設置の高さ**（ボトル下部の基準位置：床面／搬送面から ＿＿ mm）
- [ ] 反射板と設定は、**それぞれのセンサに合ったもの**を使う（各メーカーの取扱説明書に従う）
  - 既設センサ：反射板 ＿＿＿＿　感度・出力の設定はお客様のラインと同じ（＿＿＿＿）
  - KR-Qシリーズ：反射板 ＿＿＿＿（公式資料で指定のもの）　感度 ＿＿＿＿
- [ ] 一方だけ調整を手抜きしない・わざと条件を悪くしない（不公平な比較はお客様の信頼を失う）
- [ ] 2つのセンサの光が干渉しないようにした（同時に流す場合は搬送方向に十分離す、または1台ずつ流す）。方法：同時 ・ 1台ずつ
- [ ] 1台ずつ流す場合は、揺れ・間隔の条件を同じように再現できる方法を決めた

## 3. 前週まで

- [ ] 既設センサと同じ型式の実機を用意した（お客様から借用・同型品の手配）。社内記録用の型式：＿＿＿＿（画面・説明では出さない）
- [ ] KR-Qシリーズの**型式を確定**し、公式の製品ページ・仕様ページを直接開いて、現行品であること・検出距離・応答時間・光源を確認した（型式：＿＿＿＿＿＿）
  - 候補：KR-Q50N（10〜500mm）／KR-Q150NW（0.01〜1.5m）／KR-Q300NW（0.01〜2.5m）。数値は販売店掲載の値で、**公式ページ本文とは未照合**
  - 光源は公式抜粋（赤色LED）と販売店（赤外LED）で食い違うため、公式仕様で確認する（[research/product-facts.md](research/product-facts.md)）
- [ ] 取扱説明書で、検出距離・設置条件・反射板の種類を確認した（2つとも）
- [ ] 合格基準を設備担当と決めた（下の「6. 合格基準」）。流す本数：各条件・各センサ ＿＿＿ 本
- [ ] 条件の範囲を決めた（**実際のラインで起こりうる範囲に限る**）
  - 揺れ：＿＿＿＿＿＿＿＿（揺らし方・大きさ）
  - 間隔：最小 ＿＿ mm（接触させるか：する・しない）
  - 高さ：基準位置 ＿＿ mm、上 ＿＿ mm、下 ＿＿ mm（すべてボトル下部の範囲。キャップ・肩にしない）
- [ ] 本番と同じ条件でリハーサルし、両方のセンサの結果を記録した（本番で結果を作らないため）

## 4. 用意するもの

- [ ] ボトル：実物に近い透明PETボトル（中身入り・ラベル付き）＿＿本
- [ ] 検証台：小型コンベア（速度設定ができるもの）、または手送り治具
- [ ] 計数：PLC またはカウンタ（センサごとに入力を分ける）
- [ ] センサ出力の確認手段：表示灯が見える位置、またはロガー・オシロ等（＿＿＿＿＿＿）
- [ ] 高さを測る定規・スケール
- [ ] 記録用カメラ（表示灯とカウント値が同じ画面に入る位置）／書画カメラ（投影用）
- [ ] 予備：センサ・反射板・ケーブル・ボトル・電源タップ

## 5. 当日（開始30分前）

### 安全

- [ ] コンベアの可動部・挟まれ箇所にカバーがある。非常停止の位置を確認した
- [ ] 学生が立つ位置を決め、可動部に手が届かないようにした
- [ ] ケーブルを床で固定し、つまずかないようにした
- [ ] 電源・配線を確認した。ノイズ源（モーター・インバータ）から配線を離した
- [ ] 光源の注意事項を取扱説明書で確認した（2つとも。レーザ品ならクラス表示）
- [ ] 高さを変えるときは、コンベアを止めてから取付金具を調整する

### 準備

- [ ] 「1. 設置のルール」「2. 同じ条件で比べるためのルール」をもう一度確認した
- [ ] 両方のセンサの光軸を調整し、レンズと反射板を清掃した
- [ ] 表示灯が学生から見える向きになっている（または書画カメラで投影）
- [ ] PLC／カウンタを接続し、両方とも 0 にリセットした
- [ ] アプリの比較デモ画面で「実機（ライブ）」または「実機の動画」に切り替え、既設センサ・KR-Qシリーズの両方の入力欄が使えることを確認した
- [ ] 記録用カメラの録画を開始した

## 6. 合格基準（アプリの判定と同じ）

各条件・各センサで、次の **すべて** を満たしたときだけ「基準を満たした」とする。

1. **通過させた本数 ＝ センサの出力回数**（表示灯・出力の記録で数える）
2. **通過させた本数 ＝ PLCのカウント値**
3. **1本の通過中に、出力が何度も切り替わらなかった（切り替わり：なし）**

- アプリは、あわせて **過剰率 ＝（カウント値 − 通過本数）÷ 通過本数** を表示する。
- センサの出力回数と PLC のカウント値を分けて記録すると、数が増えた場所（センサ側か PLC 側か）を切り分けられる。
- 4項目（通過本数・出力回数・カウント値・切り替わりの有無）のどれかが空欄なら、アプリは判定しない（成功扱いにならない）。
- `p4-demo-height` でアプリに入力するのは**基準位置**の結果。上・下の高さの結果は [demo-record-sheet.md](demo-record-sheet.md) の補助行に書く。
- **P4-Q3 に進めるかは、KR-Qシリーズの記録だけで決まる。** 4条件すべてで基準を満たしたときだけ P4-Q3 が出る。1つでも満たさない・未記録なら `p4-followup`（結果が基準に届かなかったとき）へ進む。
- 既設センサの記録は判定には使わないが、**必ず記録する**。既設センサがデモの条件で基準を満たしても、そのまま記録し、そのまま伝える。

- [ ] 学生に予想を書いてもらった（ワークシートの「予想」欄）
- [ ] 本数を数える担当（学生1名）を決めた
- [ ] **センサ出力の確認と、PLCのカウントの確認を分けて行った**
  - センサ出力：1本の通過ごとに表示灯（または記録波形）が1回だけ切り替わるか
  - PLCのカウント：流し終えたあとのカウント値が、通過本数と一致するか
  - どちらで数が増えたのかを、メモに書く
- [ ] 各条件で、**既設センサ・KR-Qシリーズの両方**について、通過本数・出力回数・カウント値・切り替わりの有無を、その場でアプリに入力した
- [ ] 基準を満たさない結果も、そのまま記録した（言い換えない・やり直して良い結果だけを残さない）
- [ ] シミュレーション映像の数値を、結果として扱っていない
- [ ] 既設センサの結果を話すとき、メーカー名を出さず、「不良」「劣っている」と言わなかった

## 8. 結果の伝え方（p4-result）

結果は必ず3つに分けて話す。

1. **実測データ**：この場で記録した値だけ（未記録の欄は「未記録」）
2. **研修用シミュレーション**：見方の説明。結果ではない
3. **期待する改善効果**：まだ測っていない、これから実ラインで確かめること

- 改善後の数値（例：「＋0.1〜0.3%になる」）は、実測していない限り言わない・表示しない。
- 言えるのは「記録した条件での結果」と「次に確かめること」だけ。「改善した」とは言わない。
