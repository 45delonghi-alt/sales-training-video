# 進行役マニュアル

## 1. 進行役の役割

- **答えを教えない。**まず学生に考えさせ、選ばせ、選んだ結果をお客様の反応で受け止めさせる。
- **選んだ理由を聞く。**正解の数では評価しない（営業未経験の学生が対象）。
- **事実と仮説を分ける。**原因はまだ特定していない。「透明だから誤検出する」と決めつけない。
- **実機の結果を作らない。**基準を満たさなければ、そのまま「追加調査」に進む。それも営業の仕事として伝える。

### 評価する行動（ワークシートと発言で見る）

| 観点 | 見ている行動 |
|---|---|
| 現象を具体的に確認できたか | 「いつ・どのくらい」を聞いた |
| 原因を決めつけなかったか | 交換や故障の話から入らなかった。切り分けを考えた |
| 業務への影響を確認したか | 誤カウントで現場に何が起きるかを聞いた |
| 技術と課題を結びつけたか | 透明ボトルという条件と、センサの方式を結びつけた |
| 実機で検証する発想があったか | 「試してみましょう」「問題が起きた条件も確かめましょう」 |
| 結果から次の行動を考えたか | 実ラインでの検証、追加調査の提案 |

## 2. 準備（前日まで）

1. 会場のPCで `npm run experience:build` → `npm run experience:serve` を実行し、ブラウザ（Chrome または Edge）で `http://localhost:4173/` を開く。
2. 2画面の場合：右側パネルの「投影用ウィンドウを開く」→ 開いたウィンドウを投影側へ移して全画面にする（F11）。投影側で一度「クリックして投影を開始」を押す（音声を出すため）。
3. 音量・字幕を確認する（上部の 🔈 と「字幕 ON/OFF」）。
4. 実機デモ：[demo-checklist.md](demo-checklist.md) を設備担当と確認する。**合格基準（何本流して差0か）を事前に決めておく。**
5. リハーサルの最後に、進行役パネルの「最初からやり直す…」で記録を消す。

## 3. 画面の操作

| 操作 | 方法 |
|---|---|
| 進行役モード／学生画面の切り替え | 右上のボタン（進行役パネルは投影用ウィンドウには出ない） |
| 次へ・戻る | 下部のボタン、または Alt＋→ ／ Alt＋← |
| 再生・一時停止 | 映像をクリック、Space、または進行役パネルの ▶／⏸（投影用ウィンドウにも届く） |
| 選択肢を表示 | 問いの「選択肢を表示する」（考える時間のあと） |
| 解説（推奨・学習ポイント）を表示 | 進行役パネルの「解説を表示」。押すまで学生には推奨を出さない |
| 他の選択肢との比較 | 回答画面の「他の選択肢と比較する」 |
| 選び直す | 回答画面の「選び直す」（何回選んだかは記録に残る） |
| 場面へ移動 | 進行役パネルの「場面へ移動」、または上部のフェーズ名 |
| 実機デモに切り替え | 実機デモ画面の「実機（ライブ）」。録画した実機動画を使うときは「実機の動画」でファイルを選ぶ |
| 記録の保存 | 進行役パネルの「記録を保存（JSON）」「記録をコピー」 |
| 全画面 | 上部の「全画面」 |

## 4. フェーズごとの進め方とトーク例

### 導入（5分）
- 導入動画を再生する。終わったら「MISSION：飲料工場の生産トラブルを解決せよ」を板書する。
- 「ここから皆さんはオプテックス・エフエーの営業担当です。お客様の困りごとを聞いて、解決策を考えてください。」

### Phase1 現状確認（7分）
- お客様の相談を流したら、すぐに問いへ。考える時間（60秒）は**選択肢を見せない**。
- 「選択肢を見る前に、自分ならお客様に何を聞くか、ワークシートに書いてください。」
- 班ごとに A/B/C を挙手し、多い選択肢を再生する。割れたら、少数派の理由を聞いてから再生する。
- 比較画面で「Bならこれが分かった」を全員で確認してから次へ進む（Phase2 は、Bで分かった情報を前提に始まるため）。

### Phase2 原因の深掘り（9分）
- 解説「透明なボトルと光」のあと：「1本なのに2回数えることがある、かもしれない。でも、まだ原因は決まっていません。」
- 解説「どこで数が増えている？」のあと、班で1分：「どこを確かめれば、原因を切り分けられそう？」

### Phase3 真因・顧客課題（9分）
- 討議：「お客様が本当に欲しいものは、新しいセンサでしょうか？」→「正確な数量管理と、安定した生産」に導く。

### Phase4 解決提案（8分）
- 製品紹介のあと、30秒の提案トークを作る（4つの枠）。2班が発表してから、進行役パネルの「例を表示」で例を出す。
- 製品名・型式は、現行品の確認が取れるまで「確認中」の表示のままにする。

### Phase5 実機デモ・検証（12分）
1. STEP1：問い → 「検証項目と合格基準」。**試す前に合格の基準を決める**ことを強調する。
2. STEP2：シミュレーションで見方を説明する（「1本 → 検出表示1回 → カウント+1」）。そのあと「実機（ライブ）」に切り替え、本数を数えながら流す。結果を「実測を記録」に入力する。
3. STEP3：問いのあと、悪条件（位置ずれ・間隔・向き）を1つずつ実施し、それぞれ記録する。
4. STEP4：問い → 「実機デモで伝えたいこと」。
- **基準を満たさなかったら**：STEP3・4 の問いは自動で出ず、「追加調査の場面へ進む」が表示される。「うまくいかなかった理由をお客様と調べるのも営業の仕事です」と伝える。

### 振り返り（10分）
- Q1〜Q3 は各2分、Q4 は3分。出た意見を進行役パネルのメモ欄に打ち込むと、記録に残る。
- Q4 のあと、現場の例（モンタージュ）を流し、エンディングで締める。

## 5. トラブル時

| 症状 | 対処 |
|---|---|
| 音が出ない | 投影用ウィンドウで一度クリックする。音量スライダーと PC の音量を確認する |
| 映像が止まる・カクつく | 他のアプリを閉じる。字幕だけでも進行できる（セリフは字幕に出ている） |
| ブラウザを閉じてしまった | 同じPC・同じブラウザで開き直すと、続きから再開できる |
| 実機が動かない | 「シミュレーション」で見方だけ説明し、結果は「未記録」のまま。STEP3 では「追加調査の場面へ進む」を選ぶ |
| 時間が押した | Phase3 の討議と振り返り Q3 を半分にする。実機デモは削らない |
